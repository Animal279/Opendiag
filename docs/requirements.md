## 1. 范围与状态口径

- 对照基线：原工程 OpenDiag v3.8.37，包名 opendiag，Windows / Python 3.12.10 x64 / PySide6。版本与技术基线来自 A-Q31；本机复刻版本及交付状态不得冒充原版完成状态。
- 项目范围：项目A、项目A_DoCAN、项目B、demo。前三个真实项目的支持必须有项目资源与相应验收证据；Demo 运行通过不能替代真实项目验收。
- 状态沿用“未实现 → 实现中 → 待验证 → 已验收”；资料缺失、外部依赖和待决事项另列，不用“已澄清”代替实现状态。
- 每项完成必须同时关联实现位置、测试结果与适用项目。模拟、真机、视觉、冻结包验收单独记录；部分通过仍不能把整项改为已验收。
- A-Q01 提出“原版未实现项不补、死参数仅兼容、内部路径不作硬验收”的建议，**尚待用户决策**。在决策前保留文档中的完整范围及未实现项，不将它们静默移出清单。

2026-10-11 用户已确定首个公司验收目标：加载项目配置→连接 ECU→分别在 UDS 手动和 DoIP 手动页收发；UDS 例为 `10 03`→`50 03 ...`，DoIP 激活成功条件为完整 `0x0006` 响应中的结果码 `0x10`。Q10 明确正常请求载荷为 11B，先前 13B 示例为输入笔误，长度差异已关闭。旧文件格式不作为硬兼容要求，本机沿用 JSON；已连接时配置不可修改，断开后允许。此为优先级和部分产品规则，不改变下表功能状态或完整范围，见 D-11—D-15（本机资料：`local/specifications/decisions.md`）及访谈记录（本机资料：`local/replication/manual-acceptance-2026-10-11.md`）。

## 3. 必须贯穿各功能的约束

1. 依赖边界以 D01 §3.2 白名单及 A-Q15 为准，不从架构箭头推断 import 许可。Domain/Ports 保持无 Qt；UI 经 Port/Application 访问业务。组合根例外不得扩散。
2. 线程沿用 daemon 模型；UI 主线程不执行阻塞 I/O；跨线程通过事件桥接。36 快路径是主线程内直接作出下一块发送决策，实际 sendall 在发送线程，不能为追求速度阻塞 Qt 事件循环。来源：D02 §5、A-Q16。
3. 项目专属 DID、RoutineID、E2E、通道与安全参数放配置/脚本/插件，不在通用 src 中写车型分支。来源：D01 §1.2、D02 §6。
4. DoIP 发送事件载完整 DoIP 帧，DoCAN 发送事件载未分帧 UDS；“连接请求受理”与真实已连接状态分开。来源：A-Q14。
5. 每个 NRC78 场景按页面/操作分别处理，不能用一个全局重发规则覆盖手动诊断、自动化通用步骤、文件传输与刷写等待。来源：A-Q07。
6. 应用根路径统一解析，禁止照抄原电脑绝对路径。SSH 密钥、真实 keyMat 等敏感值不写入通用技术文档。来源：A-Q04/25/31。
