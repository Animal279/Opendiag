# OpenDiag UI 设计系统

版本：DS-01，2026-10-03。本文件是本机界面的设计与扩展规则，适用于现有页面、后续新增页面、公共控件和弹窗。用户已要求保留大致布局、重新设计其余视觉元素，并先写规则再修改界面。

本设计不冒充原版 QSS、图标或默认值。S01 部分截图提供区域布局参照；每个控件的业务语义、默认值、禁用条件、校验与持久化仍登记在[界面规格](ui-specification.md)。UI 的完成不代表诊断、硬件或完整视觉验收完成。

## 1. 设计目标与优先级

面向需要长期查看原始字节、指令、连接状态和通信日志的诊断工程师。界面应像工程仪表一样清楚对齐、安静、稳定；主要操作容易发现，长数据容易比较，键盘操作有明确焦点。

优先级为：数据正确和状态可信 → 清楚的操作与反馈 → 可读性及密度 → 视觉装饰。突出的是连接条和字节表格，不依靠大标题、渐变、统一阴影或层层圆角卡片建立特色。

- 保留左侧导航、顶部连接区、上方任务区、下方日志四个区域。
- 页面间使用统一主题、尺寸、状态与命名，不为单页另创一套视觉语言。
- 颜色编码动作或状态；状态同时有文字，不仅用颜色区分。
- 视觉调整不能改变固定事件语义、隐式连接设备、复制已知协议错误或改变尚未决定的恢复/互斥行为。

## 2. 布局与空间

```text
┌──────────────────────标题栏───────────────────────┐
│ 导航     │ 硬件/连接配置    连接    项目/协议/状态    │
│          ├─────────────────────────────────────────┤
│ 六个页面 │ 页面标题 / 输入 / 参数                   │
│          │ 指令、步骤、固件或业务数据表             │
│          │ 分组操作条                              │
│          ├────可拖动的任务区 / 日志分隔──────────────┤
│ 辅助工具 │ 通信日志 / 应用日志                     │
│ 折叠     │ 日志表                  复制/保存/清空    │
└──────────────────────状态栏───────────────────────┘
```

所有尺寸为 Qt 逻辑像素，随系统 DPI 缩放；不得通过固定物理像素绕过高 DPI。

| 项目 | DS-01 规则 |
| --- | --- |
| 默认/最小窗口 | 1440×860 / 1080×680；最大化和还原均需可用 |
| 标题栏 | 高 36；窗口控制命中区域至少 32×28 |
| 侧栏 | 展开宽 200，折叠宽 64；折叠保留图标、tooltip 和可访问名称 |
| 导航项 | 高 44，项间 4；选中有浅色文字、蓝色标识及背景变化 |
| 连接区 | 高 64；配置/连接动作在左，项目/协议/状态稳定地排列在右 |
| 工作区 | 常规外边距 24；窗口宽度小于 1200 时改为 16；垂直边距 16 |
| 日志区域 | 最小高度 192；内容水平内边距 16、垂直 8，以便最小窗口仍可查看完整数据行；与任务区由 4px splitter 分隔，禁止完全折叠导致入口丢失 |
| 基础间距 | 4、8、12、16、24、32；同组常用 8，组间 16，主区域间 24 |
| 工具条 | 组内 4–8；文件操作、排序/选择、删除/清空、执行操作分组；执行靠右 |
| 参数组 | 外边距 16，标签与字段间 16，行间 12；避免卡片中重复嵌套卡片 |

表格和文本编辑区承担拉伸，按钮/开关不随窗口拉长。窄窗口优先缩小空白和数据列；不可挤掉主操作、覆盖文字或让弹窗底部操作滚出屏幕。参数较多的弹窗允许内容滚动，标题、错误反馈和底部操作固定可见。

## 3. 颜色与语义

六个基础色集中定义在[主题模块](../src/ui/theme.py)的 `COLORS` 中。页面不得另写未经登记的色值。

| Token | 色值 | 使用 |
| --- | --- | --- |
| `ink` | `#263C50` | 正文、标题、深蓝灰侧栏基底 |
| `canvas` | `#F2F5F7` | 工作区背景、安静的分区间隙 |
| `surface` | `#FFFFFF` | 输入、表格、弹窗和连接区 |
| `primary` | `#2458D5` | 发送、执行、应用与键盘焦点 |
| `muted` | `#627488` | 辅助文案、表头、非主要说明 |
| `border` | `#D8E1E8` | 表格/输入轮廓、分隔线 |

派生色同样由主题集中维护：选择背景 `#EAF0FC`、悬停背景 `#F3F6FB`、禁用文字 `#8A99A8`、禁用背景 `#F2F5F7`、深侧栏文字 `#D9E4EF`、侧栏选中背景 `#34516B`。

灰底上的辅助文字使用 `muted_canvas=#5F7185`，深侧栏的选中标识与焦点使用 `sidebar_accent=#8FB4FF`。对比度计算发现基础 `muted` 与灰底仅 4.39:1，因此专门增加这两个背景适配 token：灰底文字 4.58:1，侧栏焦点对选中背景 4.00:1。页面应复用该语义，不自行加深颜色。

语义色：成功/真实已连接为 `#28785D`，警告为 `#936215`，错误/破坏性操作为 `#B94141`。演示状态必须仍写明“演示”，成功色不能证明 ECU 应答成功。TX 用主蓝、RX 用成功绿、WARN/ERROR 用相应语义色，DEBUG/INFO 使用辅助色；事件名称与数据格式不改变。

正常正文和主要辅助文本以至少 4.5:1 对比度为目标；重点状态图形与焦点至少 3:1。禁用也应可辨，并通过禁用语义和 tooltip 说明原因，不只减低透明度。主题调整需重新检查对比度。

## 4. 字体与数据排版

| 角色 | 字体/字号 | 规则 |
| --- | --- | --- |
| 中文界面 | Microsoft YaHei UI，后备 Microsoft YaHei / Segoe UI；13px | 标准正文，正常字重 |
| 页面标题 | 同界面字体，16px / 600 | 页面内只需一个主标题，不使用营销式大标题 |
| 区域标题 | 14px / 600 | 报文输入、参数组等小标题 |
| 辅助说明 | 12px | 控制说明长度，长说明换行，不塞入按钮 |
| hex、时间戳、地址 | Consolas，后备 Cascadia Mono；13px | `data_font()` 创建；只用于真实数据，不用于普通标签 |
| 主 hex 输入 | 数据字体，15px | 用大写字节及空格展示；提示说明放在输入之外 |

hex 内部仍使用 bytes。展示使用按字节分隔的大写形式，解析/合法性在统一文本边界完成；视觉格式不能增加项目专有 DID、Seed & Key 或虚构数据。

纯数字和状态列按含义居中或右对齐；文件名和描述左对齐。表头不强制全部大写。中文界面优先使用“安全访问”“功能寻址”等用户能理解的名称，可用 tooltip 保留原英文名称。长路径/描述可省略展示，但完整值保留在数据/tooltip/复制出口。

## 5. 控件规范

### 5.1 按钮与输入

- 标准按钮、单行输入、下拉、数值输入为 32px 高；主 hex 输入及相邻发送按钮为 40px。
- 控件圆角 4px；表格不圆角；分区可用 4px；不施加通用阴影。成功 toast 保留资料中的 16px 圆角。
- 按钮文字使用具体动作，如“发送”“应用到预览”“复制数据”；图标用于辅助辨认，不替代必要文字。
- `role=primary`：蓝底白字，仅表示当前区域主要提交/执行。每个工具组最多一个。
- `role=secondary`：白底描边，用于配置、文件加载等辅助动作。
- `role=quiet`：弱化轮廓，用于上移/下移、全选等本地管理。
- `role=danger`：红色文字、安静背景，用于删除/清空；与普通操作分隔，不能仅凭视觉改动新增确认/恢复行为。
- `role=connection`：描边连接按钮，真实/演示连接状态另用文字与状态标识展示；不能与发送争夺主层级。
- 正常、悬停、按下、选中、禁用、键盘焦点状态都需可辨。输入校验失败在字段附近显示准确错误，保留输入并允许修正。

### 5.2 分段选择与开关

寻址等两项互斥选择使用公共 `AddressingSelector`，显示“物理 / 功能”。默认物理；点击当前选项不取消选中或重复发出状态变化。Tab 可进入按钮，键盘能切换选项；对象名称和可访问名称明确。

保持会话等 bool 使用公共 `ToggleSwitch`：文字说明、轨道和开启/关闭状态并列。默认关闭；点击或 Space 切换，禁用时不切换；焦点清楚、不开启自动运动。选中颜色用主蓝，不与真实连接成功绿混用。

普通模式的保活开关仅已激活时可操作，委托手动服务以冻结参数和代际运行 daemon worker；显式演示仍只预览状态。`toggled(bool)` 等 Qt 信号在主线程应用；控件自身不承载业务 IO。

### 5.3 复选、下拉和数值输入

表格复选框与普通复选框保留可见勾选，至少 16px 图形、32px 行/控件命中空间。原生 Qt 状态与键盘语义保持，不用一张图伪装复选逻辑。

下拉的箭头和数值输入的增减按钮必须能发现和点击。选项、范围、单位、空值语义和默认值需在逐控件规格登记；不要用统一回退掩盖型号等必须报错的输入。

## 6. 数据表与日志

- 数据行高 32，表头高 32；保持轻微交替行背景，弱化垂直网格，但表头/边界/选中行可辨。
- 固定序号、类型、状态等短列宽，长指令/文件/描述列拉伸；允许必要的水平滚动，不把完整数据改为截断数据。
- `apply_table_style(table, data_columns=...)` 统一密度；指定的数据列由 delegate 使用数据字体，表头与说明仍用界面字体。
- 指令选中复选与表格行选择是两种不同含义，原语义保留；排序时 metadata 一起移动。
- 日志时间来自原事件 timestamp，完整 bytes 保留；通信表只转换前 171 字节为最多 512 个 hex 字符，过长另追加省略标记。
- 通信日志保留六类名称与 DEBUG 开关、5000 条淘汰规则；应用日志只显示 WARN/ERROR。蓝/绿/警告/错误色不能改变事件定义。
- 日志头部为 tab 与过滤，底部为数量及分组工具条。全文复制/导出只在用户显式操作时进行；普通模式文件导出通过 Port 在后台写入完整快照，演示仍提供文本复制。
- 空态说明下一步可做的动作，不能填入伪造诊断结果、固件或测试数据。

## 7. 弹窗、反馈与可访问性

- 参数弹窗以标题、说明、参数组和固定底部操作组织；表单标签左对齐，字段左边界对齐。
- 使用 `open()` 非阻塞 Qt 事件循环；接受/取消不等于连接、初始化或写盘。
- 主窗口关闭时关闭全部所属弹窗、停止 timer/动画、解绑订阅；真正资源释放仍由既有容器负责。
- Tab 顺序跟随视觉顺序；按钮/导航/表格/分段/开关都有焦点反馈。隐藏标签时补可访问名称和 tooltip。
- 按原资料保留成功 toast 停留 2000ms、淡出 500ms；不增加循环装饰动画。错误保持可见，不能只用自动消失提示解释必须修正的问题。
- 切换、加载、连接、执行状态用文字区分；尚未接入的真实功能明确禁用，不静默模拟成功。

## 8. 公共实现与扩展流程

公共实现位置：`src/ui/theme.py` 管理 `COLORS`、`SPACE`、`METRICS`、全局 QSS、图标、`apply_application_theme()`、`data_font()`、`apply_table_style()`；`src/ui/controls.py` 提供分段选择和开关。启动与预览共用 Fusion 调色板；页面只引用这些公共接口，不复制整段主题或直接依赖业务底层。

下拉/数值输入箭头使用 `src/ui/assets/` 中的本地 SVG，由主题解析相对包路径，包元数据显式包含资源。箭头采用 `muted` 色；调整该 token 时同步更新资源。禁用图标由公共图标工厂按禁用色绘制。

新增页面/控件按以下顺序执行：

1. 在需求与[界面规格](ui-specification.md)登记 F/Q 关联、入口与 UI 编号，标清原证据或本机设计。
2. 写出控件文案、全部选项/默认、合法范围、禁用条件、动作/快捷键、校验、持久化和生效时刻。
3. 从现有公共控件、按钮角色、字体与表格接口选用；确需新增变体时先补本文件和集中 token。
4. 页面实现依赖 PageContext/Ports/Application；共享 UI 元件不得导入 Core/Adapters/Domain，不做硬件或文件 IO。
5. 新交互写有意义的状态/键盘/错误/生命周期验证；纯色值、间距文案不增加镜像测试。
6. 按 1440×860、1080×680、折叠导航、长字段、禁用/焦点/错误状态进行渲染审查；新弹窗另查滚动与固定底部操作。
7. 同步界面规格、覆盖索引和变更记录，登记未验证的真实 Windows/DPI/视觉/业务条件。

禁止以页面私有 `setStyleSheet()` 引入随意色值和尺寸。语义化动态属性、Qt delegate、公共 painter 是允许方式。复杂新控件需先补类型/信号/状态契约，不靠仅仅“看起来相同”复用为另一种业务含义。

## 9. 验证与维护

设计规范是本机新设计的单一入口；控件事实/业务契约在界面规格，两者发生冲突时先判断是否是源事实、用户决定或实现偏差。修改设计规则时更新 DS 编号/日期、实现 token 与对应截图，保留 S01 等原参照素材。

有意义的验证包括：分段互斥/不重复状态事件、开关 Space/禁用、状态变化不触发硬件、表格数据字体/编辑不丢 bytes、最小尺寸不丢主操作、全部子弹窗关闭、旧事件不更新 UI。对比度计算与视觉渲染可以验证主题适配，但不能宣称原版像素一致或真实 Windows DPI 完全通过。

当前执行命令：`venv\Scripts\python.exe -m pytest -q`，普通/演示烟测 `main.py --smoke-test` / `main.py --ui-demo --smoke-test`；布局重现为 `tools/render_ui_preview.py`。实际结果写入覆盖索引（本机资料：`local/history/test-coverage-before-publication.md`），不在规范中预写“通过”。
