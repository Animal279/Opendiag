# OpenDiag 实施计划

2026-10-11 已按用户批准的 五项 UDS 任务（本机资料：`local/plans/2026-10-11-uds-manual.md`） 实施诊断 MAIN 闭环：显式项目加载、RA 0x10、UDS 真实 TCP、保持会话、配置锁定和完整后台日志。完成本机 loopback/UI 验证，见 本机手动诊断（本机资料：`local/specifications/manual-diagnostic.md`）。这只是 P2 首轮出口；DTC、安全访问、独立 DoIP 手动池/UDP及其他 F 功能继续按原范围推进，真 ECU 尚未验收。

本计划以[需求矩阵 F01–F21](requirements.md)为完整交付范围，以资料索引（本机资料：`local/replication/README.md`）为证据来源。P0 文档基线和 P1 工程骨架已建立，基础测试与启动通过；诊断业务、原界面还原和冻结构建尚未完成。阶段成果以本机证据更新，不能把目标表当完成记录。

## 1. 阶段安排

阶段顺序优先建立可运行、可验证的公共能力。资料补齐与硬件准备可并行开展；缺材料时继续独立工作，但关联功能不能越过验收关口。下表为本次提出的执行计划，不是原工程已存在的阶段划分。

| 阶段 | 关联需求 | 主要交付 | 进入下一阶段的条件 |
|---|---|---|---|
| P0 文档与追踪基线（已建立） | F01–F21 | 来源编号、架构边界、协作规则、功能矩阵、协议差异、资料清单、UI/测试规格 | 文档互链可用；建议与事实分开；范围遗漏检查完成 |
| P1 工程与模拟骨架（基础出口通过） | F17/F18/F20/F21 | 入口/元数据、七层包、ConfigPort/11事件、根路径、通用JSON/日志、FakeDoIPServer、六页结构壳 | 基础 pytest 与启动通过；完整业务Port、专用配置、原UI仍随对应阶段补齐 |
| P2 连接和手动诊断闭环 | F01/F02/F03/F10/F17/F18/F19/F21 | TCP 接收缓冲/解析、连接事件、RA、Alive Check、诊断与 DTC、指令列表、Demo 安全适配、基础日志 | 模拟端正常/异常/断连/NRC78 验证；手动页交互验证；真实 DLL/项目数据未就绪时明确仅 Demo |

| P4 传输、刷写、OTA 与远程流程 | F04/F11/F12/F13/F14/F16/F19/F21 | HEX/刷写步骤、流式 35/38/36/37、MD5、两套 OTA 轮询、SSH/SFTP、本地命令、签名注入、TShark/PCAP | 模拟边界及真 ECU 路径验收；签名资料不到齐则 F14 保持未完成；大文件与计时指标有测量 |
| P5 CAN、E2E 与电源 | F07/F08/F09/F10/F15/F18/F21 | ZLG/TOSUN 适配、ISO-TP、DBC/E2E、32 位安全桥、继电器/电源、项目隔离 | 两厂商独立回环；真实 E2E/27 向量；电源实际接线验证；DoCAN 已知长度边界与目标明确 |
| P6 全项目与视觉校准 | F01–F19/F21 | 四项目完整配置与脚本联调、界面逐页/弹窗/状态对照、日志与报告校准 | 三个真实项目分别有证据；截图/QSS/图标及字段齐全；所有差异明确接受或修复，不能以 Demo 代替 |

P4、P5 可在 P3 的稳定 Port 与公共传输契约上并行；真实资源尚未提供时可实现适配器边界、模拟流程和错误提示，不能声称已支持该项目。A-Q01 建议的项目验收顺序为 项目A → 项目A_DoCAN → 项目B → demo；仅作为排期建议，不减少任何项目范围。

## 2. 优先解锁材料

2026-10-11 用户确定首条公司验收为项目加载、ECU 连接和 UDS/DoIP 手动收发，见 D-11（本机资料：`local/specifications/decisions.md`）。P2 优先推进此闭环，并接入 F06 的手动原始发送；F06 的完整自动一致性执行器仍属于 P3。旧文件格式不作硬兼容前提，JSON 由本机明确设计，实际项目参数和完整日志仍需核对。此安排不缩减任何后续阶段或最终范围。

同日用户审阅方案后按 D-16（本机资料：`local/specifications/decisions.md`） 允许首轮先做好 UDS 手动、暂缓 DoIP 手动接线；当前采用这一顺序。顶部诊断断开不能整体停止手动页独立 socket 的收发。具体首轮 UDS 手动计划（本机资料：`local/plans/2026-10-11-uds-manual.md`） 已获批准并实施，实际本机出口见本文开头与覆盖索引；上段双页目标继续作为后续公司验收范围。

## 3. 实现前需要收敛的决策

- 范围：A-Q01 的“未实现项不补”、A-Q06 的 UDP 车辆发现、A-Q09/12 的固件和 ISO-TP 扩展、A-Q29 的 DoCAN 录制/轮次切分，均保留待决。不能在排期时默默删除。
- 原版缺陷：主连接已按 D-15 确定完整 0x0006 响应结果码 0x10 为激活成功，拒绝/超时提示另细化；刷写重连 0x00 的兼容、运行中切项目/手动发送、电源限幅/停止恢复、SSH 中途取消继续追踪。配置原子写入已作为可逆内部设计采用。每项记录原行为、采用行为、影响与验证方式。
- 未明语义：post 内失败、刷写失败后收尾、零字节/整块倍数、E2E 短帧、多设备同 ID、报告分母。先补证据，必要时提交具体可评审的行为选择。
- 性能：启动和 36 间隔按答复来源建立测量；TCP 无 RST、零窗口出现/持续时间独立记录。内存峰值、UI 延迟、可接受零窗口阈值尚未给出，不提前承诺数字。

## 4. 每个阶段的交付记录

每次阶段推进至少记录：F 编号、涉及项目/传输、来源与差异、实现文件、验证环境、命令或操作、结果/证据路径、未完成项及外部依赖。模拟完成但真机未验的功能状态为“待验证”，而不是“已验收”。

进入下一阶段不要求无关外部材料全部到齐，但对外发布“全部复刻完成”必须满足[最终完成标准](requirements.md#5-完成判定与关联文件)。如用户后续变更范围，在需求矩阵留下日期与决定依据，避免把阶段性取舍写成永久排除。
