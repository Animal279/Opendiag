# 资料目录与公开上传边界

2026-10-13 用户要求先整理目录，再排除敏感内容上传其余文件；已确认真实配置、原始 DOCX／问题、日志／截图和含项目参数的派生资料只留本机。

| 本机路径 | 内容 |
| --- | --- |
| `local/reference-documents/` | 原七份 DOCX、历史问题、答复和新增原 DOCX |
| `local/evidence/` | 原截图／日志、历史副本及本机预览 |
| `local/replication/` | 来源清单／哈希、答复、文本提取与核对 |
| `local/specifications/` | 项目协议、配置、接口、流程、决策和诊断记录 |
| `local/designs/`、`local/plans/` | 项目具体设计与计划 |
| `local/history/` | 整理前的完整变更和测试记录 |
| `local/backup-before-publication/` | 上传前已跟踪文件与完整旧 Git 历史 bundle |

原始资料只迁移路径，大小和 SHA-256 在移动后核对。来源清单以应用根为基准；历史问题中的旧路径按原字节保留，由来源索引说明当前位置。公开说明中的项目代号匿名化，原始完整记录在本机保留。

真实配置仍在 `config/<项目>/config.json`。公开虚构样例单独位于 `examples/projects/LoopbackDemo/`；测试和预览不读取真实配置。实际项目、用例、安全插件、固件、DBC／E2E／DTC、SDK、32 位桥与密钥材料不上传。

`.gitignore` 不会删除旧提交中的文件。首次上传使用全新安全历史，排除此前含真实资料的两次本地提交；旧历史只保存在本机 bundle。上传前核对暂存树与独立取码验证，上传后核对远程历史和文件树。不要用旧分支、tag、`--all` 或 `--mirror` 重新发布旧资料。

公开仓库不包含 `local/`；本机资料以路径说明标记，避免提供失效的 GitHub 文件链接。公司 PC 需要真实参数时，通过获准的内部方式准备本机文件。源码同步不构成硬件、视觉、性能或冻结包验收。
